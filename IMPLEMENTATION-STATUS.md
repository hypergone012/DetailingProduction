- `.env.example`: browser-safe (`VITE_*`) отдельно от server-only.

Проверки: `pnpm test` — **46 passed** (+ расшифровка push ключом подписчика, VAPID-подпись, ICS, тексты, токены); `pnpm test:api` — **15 passed** через реальный HTTP (gateway → Deno handler → PostgREST → Postgres/GoTrue/Storage), включая **реальную доставку зашифрованного Web Push по HTTPS** на локальный push-сервис (расшифровка, 410 → отключение подписки, без повторной отправки, demo — ничего не отправляет); `pnpm functions:check` (deno check) — OK.

### После выкладки — правки владельца в кабинете и удаление VERDE (2026-10-02)

Владелец настроил GRAPHITE в кабинете под себя; VERDE не нужна.

**Deploy не возвращает удалённое в кабинете.** Раньше удалённое демо-фото или выходной из конфигурации возвращались при следующем запуске Deploy: строки не было, и публикация создавала её заново. Миграция `…017_owner_removals`: `owner_delete_media` / `owner_delete_exception` записывают удаление в `private.owner_removed_config`, `api_admin_publish_tenant` такие ключи пропускает (в отчёте — `kept_owner_edits`); `--overwrite` возвращает конфигурацию, как и для изменённых строк. Остальное уже было так: изменённые строки (`config_sig = null`) не перезаписываются, режим работы публикация не понижает.

**Удаление студии.** Миграция `…018_remove_tenant`: `api_admin_remove_tenant(slug, dry_run)`, только service_role. Отказ для студии, которая работает или когда-либо работала (live / `live_since`). Удаление одним `delete` — всё каскадом. Возвращает список файлов в Storage и входы владельцев, которые больше ни к какой студии не относятся. `pnpm tenant:remove <slug> [--dry-run]` удаляет файлы, студию и эти входы. Отказ, если `tenants/<slug>/` ещё в репозитории; повторный запуск — no-op. В Deploy — поле `remove_studios`.

Папка `tenants/verde` удалена. Из продакшена VERDE удаляется запуском Deploy с `remove_studios = verde`.
